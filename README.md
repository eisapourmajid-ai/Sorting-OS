# SORTING OS — مخزن مهندسی و سورس قابل توسعه

نرم‌افزار دسکتاپ محلی برای عملیات سورتینگ و بسته‌بندی میوه، باسکول، محموله، موجودی، تسویه و حسابداری. رابط کاربری فارسی/RTL و اجرای آفلاین، اصول هدف هستند.

> **وضعیت صادقانه (به‌روزرسانی ۱۴۰۵/۰۷/۲۷ — 2026-10-19):** هستهٔ دامنه/مالی جدید در `desktop/sorting_os/` پیاده‌سازی شده و با ۲۰۹ آزمون headless پوشش داده شده است (۱۷ آزمون پایهٔ قبلی + ۱۹۲ آزمون جدید). **اما:** رابط گرافیکی در این محیط اجرا نشده (tkinter نصب نیست ⇒ `NOT RUN`)، روی Windows 7 SP1 x64 آزموده نشده (`NOT VERIFIED ON TARGET OS`)، ساخت EXE/نصب‌کننده انجام نشده (`NOT RUN`)، و تصمیم‌های تجاری کلیدی (مدل کسب‌وکار، درصد صافی، بهای تمام‌شده، کدینگ نهایی، سال مالی) هنوز «باز» هستند و در `docs/open-decisions.md` فهرست شده‌اند. هیچ‌یک از این موارد نباید «تأییدشده» تلقی شود.

## شروع سریع

1. فایل `docs/agent-system/UPLOAD_FIRST_ORDER_FA.md` را بخوانید.
2. به عامل کدنویس ابتدا `MASTER_PROMPT_FOR_AGENT_FA.md`، `PROJECT_SPEC.md`، اسناد مالی مرجع و وضعیت پیاده‌سازی را بدهید.
3. فقط `prompts/00-repository-audit-and-state-map.md` را اجرا کنید. قبل از ممیزی، بازنویسی/توسعه گسترده نکنید.
4. مراحل 00 تا 35 را به ترتیب و با گیت پذیرش اجرا کنید. هر مرحله باید گزارش شواهد واقعی داشته باشد.

## فایل‌های اصلی

- `desktop/sorting_os/core.py` — **تنها منبع حقیقت واحد پول و تقویم**: `int` ریال، ۱ تومان = ۱۰ ریال، بدون float، تبدیل بدون اتلاف؛ موتور تقویم شمسی آفلاین (۱۴ لنگر + رفت‌وبرگشت ۷۳٬۳۲۳ روزه، بدون خطا).
- `desktop/sorting_os/db.py` + `migrations.py` — persistence، تراکنش `BEGIN IMMEDIATE`، migration نسخه‌دار، backup/restore.
- `desktop/sorting_os/services/` — دامنه: اشخاص و تطبیق، محصول/درجه/بسته‌بندی، محموله و توزین، سورتینگ با توازن جرم، انبار و رزرو، ارسال، فاکتور و هزینه، دفترکل دوبل و معین طرف حساب، موتور صافی، بانک و چک، import/export، گزارش و KPI، چاپ، دورهٔ مالی.
- `desktop/sorting_os/ui/app.py` — پوستهٔ فارسی/RTL (بخش‌های عملیاتی + حسابداری)؛ **در این محیط اجرا نشده است**.
- `desktop/accounting_core.py` — دفترکل دوبل، برگشت سند، تراز آزمایشی، ترازنامه، سود و زیان، جریان نقد و نسبت‌های پایه.
- `desktop/tests/` — آزمون‌های واحد و تست‌های invariant (بدون tkinter، بدون شبکه، دادهٔ مصنوعی).
- `docs/financial/` — قراردادهای مرجع واحد پول، حسابداری دوبل، صورت‌های مالی و سناریوهای پذیرش.
- `docs/requirements-traceability.csv` — ردیابی نیازمندی‌ها با وضعیت جداگانهٔ `implemented/partial/missing/blocked` و سطح شواهد `DESIGNED/IMPLEMENTED/TESTED/VERIFIED ON TARGET`.
- `docs/open-decisions.md` — تصمیم‌های تجاری باز و اثر آن‌ها بر قابلیت‌های وابسته.

## اجرا

نیاز: Python 3.8+ با Tkinter و SQLite؛ برای سیستم هدف موردنظر باید ماتریس محیط را جداگانه آزمود
(`docs/architecture/platform-compatibility-matrix.md`).

Windows:

```bat
cd desktop
run_windows.bat
```

یا از پوشه `desktop`:

```bash
python main.py
python -m unittest discover -s tests -v
```

بررسی لینک‌ها و مسیرهای اسناد (بدون نیاز به نصب چیزی):

```bash
python3 scripts/check-doc-links .
```

برنامه برای قابلیت‌های اصلی به شبکه نیاز ندارد. دیتابیس در مسیر داده محلی کاربر است؛ سورس با دیتابیس زنده مخلوط نشود.

## حسابداری و مبالغ

مبالغ دفترکل در `integer rial` ذخیره می‌شوند؛ ۱ تومان = ۱۰ ریال. واحد ورودی و نمایش قابل انتخاب است و روی هر گزارش/چاپ واحد مبلغ درج می‌شود. صورت‌های مالی از سندهای دفترکل ساخته می‌شوند، نه از وضعیت ظاهری فاکتورهای قدیمی. جدول فاکتور MVP قدیمی از نوع REAL است؛ تا تأیید واحد و تطبیق داده، auto-post یا مهاجرت آن به دفترکل ممنوع است (فاکتور legacy با `amount_rial IS NULL` اصلاً قابل posting نیست).

سند قطعی حذف یا بازنویسی بی‌ردپا نمی‌شود؛ اصلاح فقط با سند معکوس انجام می‌شود. posting هر منبع عملیاتی کلید یکتا دارد (retry سند تکراری نمی‌سازد).

**درصد صافی** یک ویژگی قابل تخصیص است (DEC-017): نرخ **پیش‌فرض** (قابل ویرایش)، نرخ هر **حساب طرف**
و نرخ هر **فاکتور**؛ ترتیب اعمال «فاکتور ← طرف ← پیش‌فرض» و ورود دستی هنگام محاسبه بالاتر از
همه. هر نرخ نسخه‌دار است، پس ویرایش نرخ صافی‌های قبلی را تغییر نمی‌دهد؛ اگر نرخی نباشد، محاسبه
با پیام روشن رد می‌شود. گزارش: `reports/SETTLEMENT_RATE_ASSIGNMENT.md`.

گزارش جریان وجوه نقد و برخی نسبت‌ها در این نسخه برچسب **مدیریتی/پایه** دارند و قبل از اتکای رسمی باید mapping و طبقه‌بندی آنها توسط حسابدار تأیید شود.

## آزمون و ادعای سازگاری

- خط مبنا: ۱۷ آزمون پایهٔ MVP (پاس‌شده).
- وضعیت فعلی: **۲۰۹ آزمون** با `python -m unittest discover -s tests` (از پوشهٔ `desktop`) — اجرای واقعی و خروجی در `reports/`.
- پاس‌شدن آزمون‌های واحد به معنای تأیید UI، نصب، چاپگر یا Windows 7 نیست. هیچ وضعیت `VERIFIED ON TARGET` بدون مشاهدهٔ مستقیم روی سیستم هدف ثبت نشود.
- گزارش‌های شواهد هر مرحله در `reports/` نگهداری می‌شود (`INITIAL_REPOSITORY_AUDIT.md`، `BASELINE_EVIDENCE.md`، `PROMPT_*.md`).
