# SORTING OS — مخزن مهندسی و سورس قابل توسعه

نرم‌افزار دسکتاپ محلی برای عملیات سورتینگ و بسته‌بندی میوه، باسکول، محموله، موجودی، تسویه و حسابداری. رابط کاربری فارسی/RTL و اجرای آفلاین، اصول هدف هستند.

> **وضعیت صادقانه:** این بسته شامل سورس MVP، یک هسته حسابداری دوبل قابل اجرا و گزارش‌های پایه متصل به دفترکل، مستندات مرجع و ۳۶ پرامپت مرحله‌ای است. محصول کامل و آماده استفاده رسمی حسابداری نیست. آزمون روی Windows 7 SP1 x64، ساخت EXE/installer، تقویم شمسی در هسته گزارش مالی، بسته‌شدن دوره، گزارش‌های مالیاتی/قانونی، چرخه کامل بانک/چک، صافی و گردش کامل انبار/سورتینگ هنوز نیازمند توسعه و پذیرش هستند.

## شروع سریع

1. فایل `docs/agent-system/UPLOAD_FIRST_ORDER_FA.md` را بخوانید.
2. به عامل کدنویس ابتدا `MASTER_PROMPT_FOR_AGENT_FA.md`، `PROJECT_SPEC.md`، اسناد مالی مرجع و وضعیت پیاده‌سازی را بدهید.
3. فقط `prompts/00-repository-audit-and-state-map.md` را اجرا کنید. قبل از ممیزی، بازنویسی/توسعه گسترده نکنید.
4. مراحل 00 تا 35 را به ترتیب و با گیت پذیرش اجرا کنید. هر مرحله باید گزارش شواهد واقعی داشته باشد.

## فایل‌های اصلی

- `desktop/main.py` — رابط Tkinter فارسی، بخش‌های عملیاتی MVP و صفحه حسابداری/گزارش.
- `desktop/database.py` — ذخیره‌سازی عملیاتی SQLite.
- `desktop/accounting_core.py` — واحد پول دقیق، دفترکل دوبل، برگشت سند، تراز آزمایشی، ترازنامه، سود و زیان، جریان وجوه نقد، نسبت‌های پایه و دفتر حساب.
- `desktop/tests/` — آزمون‌های واحد برای هسته عملیاتی و حسابداری.
- `docs/financial/` — قراردادهای مرجع واحد پول، حسابداری دوبل، صورت‌های مالی و سناریوهای پذیرش.
- `prompts/` — ۳۶ پرامپت تخصصی 00–35.
- `contracts/` — گیت‌ها، گزارش عامل، ردیابی نیازمندی‌ها و قیود صحت داده.
- `reference-inputs/` — مراجع اولیه و نسخه‌های قبلی جهت حفظ تاریخچه و حل تعارض؛ مراجع قدیمی نباید بر اسناد canonical مالی جدید غلبه کنند.

## اجرا

نیاز: Python 3.8+ با Tkinter و SQLite؛ برای سیستم هدف موردنظر باید ماتریس محیط را جداگانه آزمود.

Windows:

```bat
cd desktop
run_windows.bat
```

یا از پوشه `desktop`:

```bash
python main.py
python -m unittest discover -s tests -v
```

برنامه برای قابلیت‌های اصلی به شبکه نیاز ندارد. دیتابیس در مسیر داده محلی کاربر است؛ سورس با دیتابیس زنده مخلوط نشود.

## حسابداری و مبالغ

مبالغ دفترکل در `integer rial` ذخیره می‌شوند؛ ۱ تومان = ۱۰ ریال. واحد ورودی و نمایش قابل انتخاب است. صورت‌های مالی از سندهای دفترکل ساخته می‌شوند، نه از وضعیت ظاهری فاکتورهای قدیمی. جدول فاکتور MVP قدیمی از نوع REAL است؛ تا تأیید واحد و تطبیق داده، auto-post یا مهاجرت آن به دفترکل ممنوع است.

گزارش جریان وجوه نقد و برخی نسبت‌ها در این نسخه برچسب **مدیریتی/پایه** دارند و قبل از اتکای رسمی باید mapping و طبقه‌بندی آنها توسط حسابدار تأیید شود.

## آزمون و ادعای سازگاری

در ساخت این بسته، ۱۷ آزمون واحد پاس شده‌اند؛ اجرای آزمون را در محیطی که از آن استفاده می‌کنید دوباره انجام دهید. پاس‌شدن آزمون‌های واحد به معنای تأیید UI، نصب، چاپگر یا Windows 7 نیست. هیچ وضعیت `VERIFIED ON TARGET` بدون مشاهده مستقیم روی سیستم هدف ثبت نشود.
