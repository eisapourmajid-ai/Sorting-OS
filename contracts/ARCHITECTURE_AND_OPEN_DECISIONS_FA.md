# معماری فعلی و تصمیم‌های باز — وضعیت تحویل

## وضعیت مشاهده‌شده
- مخزن شامل مستندات دامنه، مدل داده، حسابداری/صافی، UI، معماری آفلاین/Windows 7، چاپ، امنیت، تست‌ها و راهنمای agent است.
- شاخه توسعه `feature/desktop-mvp-foundation` برای افزودن desktop MVP ایجاد شده و Pull Request شماره ۱ به‌صورت Draft ساخته شده است.
- MVP فعلی: Python/Tkinter + SQLite محلی، فایل‌های `desktop/main.py`, `desktop/database.py`, تست‌ها و scripts.
- این انتخاب با هدف Windows 7 باید از نظر نسخه runtime، Tk/Tcl، PyInstaller و چاپگر هدف روی دستگاه واقعی آزمایش شود.

## تصمیم‌های باز که نباید حدس زده شوند
1. آیا Windows 7 SP1 x64 الزام قطعی است یا فقط پشتیبانی ترجیحی؟
2. آیا نرم‌افزار روی یک رایانه اجرا می‌شود یا چند کاربر/چند رایانه؟
3. مدل قرارداد: امانی/کارمزدی، خریدوفروش، یا هر دو؟ مالکیت کالا در هر مسیر چیست؟
4. مبنای دقیق صافی، تخفیف، کمیسیون، افت، ضایعات، هزینه قابل کسر و rounding.
5. روش بهای تمام‌شده/ارزش‌گذاری موجودی و حساب‌های مرتبط.
6. تقویم عملیاتی شمسی و نحوه ذخیره تاریخ/منطقه زمانی.
7. پول پایه، نمایش تومان/ریال، دقت و قانون گرد کردن.
8. چه کسی حق قطعی کردن، اصلاحیه، ادغام اشخاص، restore دیتابیس و صادرات مالی دارد؟
9. الگوهای چاپ رسمی، سربرگ، فیلدهای اجباری و چاپگرهای هدف.
10. فایل‌های واقعی بانک/حسابداری کدام قالب‌ها و encodingها دارند؟ قبل از طراحی adapter دقیق، نمونه ناشناس لازم است.

تا تصویب تصمیم، داده خام باید حفظ شود و قابلیت وابسته به تصمیم تجاری نباید اثر مالی نهایی تولید کند.


## قرارداد جدید واحد پول و مرز legacy

هسته دفترکل جدید در `desktop/accounting_core.py` مبنای مبلغ `integer rial` و تبدیل تومان از طریق `Decimal` را اجرا می‌کند. این هسته در همان SQLite ذخیره می‌شود، اما جدول‌های MVP عملیاتی (خصوصاً `invoices.amount REAL`) تا زمانی که واحد پول و قواعد posting/reconciliation مصوب نشده‌اند، از دفترکل جدا می‌مانند. هر اتصال باید به‌صورت migration و application service صریح، versioned و idempotent ساخته شود؛ auto-post بدون مصوبه ممنوع است.

## تصمیم‌های باز باقیمانده

- تقویم شمسی آفلاین و آزمون کامل کبیسه/مرز سال؛
- سال مالی، افتتاحیه، بستن دوره و انتقال سود/زیان؛
- کدینگ/تفصیلی‌ها و طبقه‌بندی جاری/غیرجاری؛
- mapping جریان وجوه نقد و تأیید حسابدار؛
- اتصال posting به فاکتور، صافی، بانک و چک؛
- انطباق رسمی/مالیاتی و سیستم‌عامل هدف.
