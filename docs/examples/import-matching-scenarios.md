# سناریوهای تست تطبیق اشخاص

سناریوها باید در test database اجرا و بعد از تست پاک‌سازی شوند.

| ID | داده واردشده | داده موجود | نتیجه مورد انتظار |
|---|---|---|---|
| PM-01 | شناسه ملی معتبر برابر، نام کمی متفاوت | یک Party با همان ملی | پیشنهاد match قوی؛ بررسی اختلاف نام؛ بدون Party تکراری |
| PM-02 | شناسه ملی معتبر متفاوت، نام مشابه | Party موجود | `CONFLICT`؛ merge خودکار ممنوع |
| PM-03 | ملی خالی، تلفن نرمال‌شده برابر، نام مشابه | Party موجود | کاندید؛ نیازمند تأیید براساس سیاست |
| PM-04 | فقط نام مشابه | Party موجود | کاندید کم‌اطمینان؛ نه merge خودکار |
| PM-05 | یک شماره تماس برای چند عضو خانواده | چند Party | تشخیص ambiguity؛ تلفن تنها تعیین‌کننده نیست |
| PM-06 | نام دارای نیم‌فاصله/فاصله یا حروف متفاوت | Party موجود | جستجوی نرمال‌شده؛ اصل متن حفظ شود |
| PM-07 | دو ردیف تکراری در فایل با یک ملی | هنوز در فایل import | یک کاندید/duplicate با لینک به هر دو ردیف منبع؛ گزارش کامل |
| PM-08 | شخص موجود دارای نقش مالک؛ فایل نقش خریدار را معرفی می‌کند | همان شخص | در صورت تأیید هویت، افزودن نقش دوم به همان Party |
| PM-09 | ادغام دو شخص با اسناد و گردش حساب | دو Party | مجوز ویژه، audit، حفظ اسناد، FKهای معتبر و reconciliation پیش/پس |
| PM-10 | خطا در میانه عملیات merge | دیتابیس شامل داده مرتبط | rollback کامل؛ هیچ FK یتیم یا اثر نیمه‌تمام |

## معیار پذیرش
نتایج باید با شناسه سناریو و خروجی واقعی تست ثبت شوند. نام‌بردن از سناریو بدون اجرای test به معنی PASS نیست.
