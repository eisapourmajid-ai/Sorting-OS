# تبادل داده، تطبیق اشخاص و جریان تخصیص سند/چاپ

## 1. هدف
یک زیرسامانه مشترک برای import/export و تطبیق اشخاص تعریف می‌کند. هیچ ماژولی parser، منطق duplicate یا merge مستقل و ناسازگار نسازد.

## 2. جریان عمومی واردسازی
`انتخاب فایل → تشخیص ساختار → انتخاب sheet/header → نگاشت ستون‌ها → پیش‌نمایش → اعتبارسنجی → تشخیص تکراری → بازبینی تعارض → commit → گزارش دسته واردسازی`

### الزامات
- ورودی‌ها فقط محلی‌اند؛ فایل به وب‌سرویس ارسال نشود.
- ردیف خام، نام فایل، sheet و شماره ردیف منبع، زمان و کاربر، شناسه batch و نتیجه هر ردیف نگهداری شود.
- تاریخ شمسی متنی، تاریخ واقعی اکسل، تاریخ میلادی، زمان جدا/چسبیده، ثانیه و جداکننده هزارگان پشتیبانی یا با پیام صریح رد شوند.
- هر خطا باید جای دقیق و راه اصلاح داشته باشد. پیش‌نمایش پیش از تغییر پایدار الزامی است.
- commit transactional یا checkpointشده باشد؛ نتیجه نیمه‌کاره مبهم ممنوع.
- خروجی فقط فیلدهای مجاز را شامل شود؛ مقادیر CSV شروع‌شونده با `=`, `+`, `-`, `@` باید در برابر formula injection ایمن شوند.

## 3. تطبیق اشخاص

### اولویت شواهد
1. شناسه ملی معتبر و برابر.
2. شماره تماس نرمال‌شده، با بررسی شماره مشترک یا قدیمی.
3. نام نرمال‌شده + شواهد تکمیلی مانند شناسه قدیمی، شهر یا نشانی.
4. نام به تنهایی صرفاً کاندید می‌سازد؛ اجازه merge خودکار نمی‌دهد.

### وضعیت هر ردیف
`NEW`, `MATCH_CANDIDATE`, `MATCH_CONFIRMED`, `CONFLICT`, `INVALID`, `SKIPPED`.

### تعارض‌ها
- دو شناسه ملی متفاوت: تعارض بحرانی.
- نام مشابه و شناسه ملی غایب: بررسی انسانی.
- شخص موجود با چند نقش: نقش جدید به همان Party فقط پس از تأیید مطابقت اضافه شود؛ Party تکراری نساز.
- فایل ممکن است ردیف‌های قدیمی و جدید را در هر ترتیبی داشته باشد؛ الگوریتم نباید شماره ردیف خاصی را معادل قدیمی/جدید فرض کند.

### ادغام
- صفحه مقایسه قبل از ادغام؛ مجوز ویژه؛ دلیل؛ audit؛ انتقال روابط در تراکنش؛ نگهداری شناسه/مشخصات منبع؛ reconciliation شمار روابط و مانده؛ مسیر undo/recovery.
- اسناد قطعی حذف یا بازنویسی نشوند؛ FKهای مرتبط اصلاح شوند.

## 4. اتصال سند مرتبط
در فرم فاکتور/صافی یک پنل «اسناد مرتبط» نمایش داده شود که بر اساس Party، Shipment، Dispatch و نوع سند جستجو می‌کند. کاربر ردیف‌های لازم را انتخاب می‌کند. انتخاب باید در جدول relation واقعی ذخیره شود. چاپ باید انتخاب‌ها را از snapshot مجاز بخواند؛ متن آزاد به‌تنهایی ارتباط دامنه‌ای نیست.

## 5. export
- انتخاب فیلدها، ترتیب، فیلتر، قالب تاریخ/عدد و عنوان ستون‌ها.
- شناسه داخلی حساس را فقط در صورت مجوز صادر کن؛ برای تبادل، شناسه خارجی/legacy پایدار ارائه بده.
- export از گزارش باید با فیلتر صفحه برابر باشد؛ اطلاعاتی که کاربر حق دیدن ندارد صادر نشود.

## 6. معیار آزمون
- فایل خالی/خراب؛ header جابه‌جا؛ ستون اضافه/گم‌شده؛ فایل تکراری؛ ردیف تکراری داخل فایل؛ مبلغ دارای هزارگان؛ تاریخ شمسی/میلادی؛ شخص با ملی یکسان؛ ملی متفاوت؛ ملی غایب؛ شماره مشترک؛ نام‌های با نیم‌فاصله؛ تعارض؛ لغو قبل از commit؛ خطا در میانه commit؛ بازگشایی batch؛ export با فیلتر و data permission.
