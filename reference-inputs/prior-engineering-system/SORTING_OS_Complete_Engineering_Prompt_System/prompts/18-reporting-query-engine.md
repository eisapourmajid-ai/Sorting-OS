# فاز 18 — گزارش‌ها، داشبورد و تعریف شاخص‌ها

**شناسه:** SORTING-OS-P18  
**محدوده:** هر KPI یک تعریف محاسباتی و مسیر جزئیات دارد.

## دستور قابل کپی برای عامل برنامه‌نویس

تو در حال کار روی مخزن واقعی SORTING OS هستی. دستور مادر `MASTER_PROMPT.md` و فایل‌های مرجع `PROJECT_SPEC.md` و مستندات مرتبط را رعایت کن. **فقط همین مرحله را اجرا کن؛ فازهای بعد را آغاز نکن.**

### هدف
گزارش‌های عملیاتی و مالی را از queryهای واقعی بساز و تعریف هر عدد را شفاف کن.

### کارهای دقیق
- فهرست گزارش‌ها را با کاربر/هدف/فیلتر/دانه‌بندی/ستون/تعریف فرمول/مجوز/خروجی و آزمون پذیرش ثبت کن.
- داشبورد روزانه شامل وزن ورودی/خروجی، موجودی فیزیکی و قابل تخصیص، محموله فعال، اسناد در انتظار بررسی، مغایرت، مانده دریافتنی/پرداختنی، صافی باز و هزینه‌ها باشد؛ هر کارت فقط اگر query معتبر وجود دارد فعال شود.
- تعریف بازه زمانی، تاریخ سند در برابر تاریخ ثبت، وضعیت پیش‌نویس در برابر قطعی، لغو/برگشت و منطقه زمانی/تقویم را یکنواخت کن.
- drill-down از KPI به ردیف‌ها و سندهای مبنا داشته باش. جمع نمودار باید با جدول جزئیات همخوان باشد.
- pagination، sorting، filter persistence، خروجی CSV/XLSX و احترام به مجوزهای دسترسی را رعایت کن.
- از queryهای N+1 و loading طولانی جلوگیری کن؛ indexها از query profile واقعی تعیین شوند.
- داده نمایشی یا نمونه از محیط production حذف شود. حالت empty/error/partial-data صادقانه نمایش داده شود.

### معیار پذیرش
تست aggregate در برابر dataset شناخته‌شده، بازه مرزی تاریخ، سند لغوشده/برگشتی، مجوز، export، pagination و drill-down اجرا شود.


## قرارداد مشترک اجرا (الزامی)

این پرامپت را در مخزن واقعی اجرا کن، نه بر اساس حدس. قبل از تغییر، دستور مادر و اسناد مربوط را بخوان؛ `git status`، branch و commit را ثبت کن؛ تغییرات کاربر را دست‌نخورده نگه دار. محدوده این پرامپت تنها محدوده مجاز همین نوبت است. قبل از پیاده‌سازی، فایل‌های محتمل، وابستگی‌ها، خطر داده، اثر UI/مجوز/گزارش، migration و تست را مشخص کن. اگر یکی از قواعد تجاری لازم نامشخص است، به‌جای حدس‌زدن تصمیم باز ثبت کن و بخش وابسته را اجرا نکن. پس از تغییر، build و تست واقعی اجرا کن، diff را مرور کن، اسناد را به‌روز کن و گزارش انتهایی قالب دستور مادر را بده. موفقیت build یا تست، سازگاری Windows 7 یا آفلاین‌بودن را بدون شواهد ادعا نکن. در این نوبت به پرامپت بعدی نرو.
