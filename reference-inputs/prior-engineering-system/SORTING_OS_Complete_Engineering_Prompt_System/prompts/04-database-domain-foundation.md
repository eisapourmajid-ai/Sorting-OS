# فاز 04 — مدل داده، مهاجرت و قرارداد دامنه

**شناسه:** SORTING-OS-P04  
**محدوده:** قواعد را در دیتابیس و دامنه قابل دفاع کن.

## دستور قابل کپی برای عامل برنامه‌نویس

تو در حال کار روی مخزن واقعی SORTING OS هستی. دستور مادر `MASTER_PROMPT.md` و فایل‌های مرجع `PROJECT_SPEC.md` و مستندات مرتبط را رعایت کن. **فقط همین مرحله را اجرا کن؛ فازهای بعد را آغاز نکن.**

### هدف
مدل داده‌ای بساز که عملیات واقعی و تاریخچه اسناد را پشتیبانی کند، بدون اینکه قواعد حسابداری فقط در event handler یا queryهای پراکنده دفن شوند.

### کارهای دقیق
1. مدل فعلی و تمام مصرف‌کننده‌ها را بازبینی کن؛ مدل موازی و جدول‌های هم‌معنی ایجاد نکن.
2. کلید داخلی پایدار، foreign key، unique constraints، indexهای کاربردی، not-null و قواعد حذف را طراحی کن. حذف آبشاری اسناد مالی/انبار ممنوع؛ روابط حساس باید با محدودیت یا آرشیو کنترل شوند.
3. شناسه داخلی و شماره نمایشی سند را تفکیک کن. شماره نمایشی ممکن است بر اساس سال/نوع سند قالب‌بندی شود، اما کلید ذخیره‌سازی نباشد.
4. تاریخ ثبت، تاریخ سند، زمان ثبت، کاربر ثبت‌کننده، کاربر تأییدکننده، وضعیت و version/concurrency token را در اسناد لازم نگه دار.
5. موجودی را از InventoryTransaction و مانده را از اسناد قطعی و قواعد posting بازسازی‌پذیر کن؛ cache/summary فقط اگر راه بازسازی و کنترل reconciliation داشته باشد.
6. Domain services/use cases را برای وزن خالص، تراز سورتینگ، تخصیص هزینه، تخصیص فاکتور، وضعیت سند، تسویه و posting بساز یا کامل کن.
7. migration نسخه‌دار اضافه کن؛ نمونه دیتابیس تولیدی را مستقیم و دستی دستکاری نکن. برنامه ارتقا، backup پیش از ارتقا، خطای میانه و downgrade/forward-fix را توضیح بده.
8. آزمون‌های invariant و property/edge cases اضافه کن: صفر/منفی، اعداد بسیار بزرگ، گردکردن، ردیف تکراری، FK یتیم، transaction rollback و concurrency.

### معیار پذیرش
داده ناسازگار تا حد ممکن در مرز ذخیره‌سازی ممنوع باشد؛ قواعد دامنه واحد و آزمون‌پذیر باشند؛ migration روی دیتابیس جدید و نمونه نسخه قبلی اجرا و نتیجه مستند شود.


## قرارداد مشترک اجرا (الزامی)

این پرامپت را در مخزن واقعی اجرا کن، نه بر اساس حدس. قبل از تغییر، دستور مادر و اسناد مربوط را بخوان؛ `git status`، branch و commit را ثبت کن؛ تغییرات کاربر را دست‌نخورده نگه دار. محدوده این پرامپت تنها محدوده مجاز همین نوبت است. قبل از پیاده‌سازی، فایل‌های محتمل، وابستگی‌ها، خطر داده، اثر UI/مجوز/گزارش، migration و تست را مشخص کن. اگر یکی از قواعد تجاری لازم نامشخص است، به‌جای حدس‌زدن تصمیم باز ثبت کن و بخش وابسته را اجرا نکن. پس از تغییر، build و تست واقعی اجرا کن، diff را مرور کن، اسناد را به‌روز کن و گزارش انتهایی قالب دستور مادر را بده. موفقیت build یا تست، سازگاری Windows 7 یا آفلاین‌بودن را بدون شواهد ادعا نکن. در این نوبت به پرامپت بعدی نرو.
