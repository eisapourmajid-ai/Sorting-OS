# فاز 22 — آزمون خودکار، یکپارچه و End-to-End

**شناسه:** SORTING-OS-P22  
**محدوده:** درستی سیستم با سناریوی کسب‌وکار ثابت شود.

## دستور قابل کپی برای عامل برنامه‌نویس

تو در حال کار روی مخزن واقعی SORTING OS هستی. دستور مادر `MASTER_PROMPT.md` و فایل‌های مرجع `PROJECT_SPEC.md` و مستندات مرتبط را رعایت کن. **فقط همین مرحله را اجرا کن؛ فازهای بعد را آغاز نکن.**

### هدف
از مجموعه تست‌های پراکنده به ماتریس رگرسیون قابل تکرار برس.

### کارهای دقیق
- هر Requirement ID را به تست unit/domain، integration/database، UI/workflow و در صورت نیاز compatibility وصل کن.
- تست داده‌های مالی/وزن را با اعداد known-answer و expected output versioned ذخیره کن؛ از assertهای مبهم پرهیز کن.
- سناریوی کامل پایه: Party → ورود/باسکول → Shipment → SortingOperation → خروجی‌های چندگانه → Inventory → Dispatch → Weigh-out → Invoice/Expense → Settlement draft → review/approve → receipt/payment → journal posting → bank match → report/print.
- سناریوهای خطا: دوبار کلیک، retry بعد از timeout، قطع برق/فرآیند، migration، موجودی ناکافی، همزمانی دو اپراتور، دسترسی غیرمجاز، تعارض import، شخص تکراری، کارمزد بانکی، print multi-page و backup/restore.
- fixtureها باید deterministic و محدود به test database باشند؛ test data در دیتابیس واقعی تولید نشود.
- تست‌ها ترتیب وابسته نداشته باشند و پس از اجرا محیط را cleanup یا ایزوله کنند.
- آمار coverage را به‌تنهایی معیار کیفیت ندان؛ business invariants و مسیرهای failure مهم‌ترند.
- هر bug بازتولیدپذیر ابتدا به regression test تبدیل شود.

### معیار پذیرش
ماتریس پوشش، فرمان‌های قابل اجرا، داده آزمون مستند و گزارش دقیق پاس/فیل ارائه شود؛ تست flaky یا غیرفعال‌سازی تست برای سبزکردن build ممنوع است.


## قرارداد مشترک اجرا (الزامی)

این پرامپت را در مخزن واقعی اجرا کن، نه بر اساس حدس. قبل از تغییر، دستور مادر و اسناد مربوط را بخوان؛ `git status`، branch و commit را ثبت کن؛ تغییرات کاربر را دست‌نخورده نگه دار. محدوده این پرامپت تنها محدوده مجاز همین نوبت است. قبل از پیاده‌سازی، فایل‌های محتمل، وابستگی‌ها، خطر داده، اثر UI/مجوز/گزارش، migration و تست را مشخص کن. اگر یکی از قواعد تجاری لازم نامشخص است، به‌جای حدس‌زدن تصمیم باز ثبت کن و بخش وابسته را اجرا نکن. پس از تغییر، build و تست واقعی اجرا کن، diff را مرور کن، اسناد را به‌روز کن و گزارش انتهایی قالب دستور مادر را بده. موفقیت build یا تست، سازگاری Windows 7 یا آفلاین‌بودن را بدون شواهد ادعا نکن. در این نوبت به پرامپت بعدی نرو.
