# فاز 17 — صورت‌حساب بانکی، تطبیق، چک و مغایرت‌گیری

**شناسه:** SORTING-OS-P17  
**محدوده:** تراکنش بانکی مستقل از برداشت/واریز حسابداری اولیه است.

## دستور قابل کپی برای عامل برنامه‌نویس

تو در حال کار روی مخزن واقعی SORTING OS هستی. دستور مادر `MASTER_PROMPT.md` و فایل‌های مرجع `PROJECT_SPEC.md` و مستندات مرتبط را رعایت کن. **فقط همین مرحله را اجرا کن؛ فازهای بعد را آغاز نکن.**

### هدف
ورود صورت‌حساب بانک از فایل محلی، تطبیق با دریافت/پرداخت و مدیریت چک را قابل ممیزی کن.

### واردسازی
- XLSX/CSV با sheet/header قابل انتخاب، mapping قابل اصلاح، date/time یک‌ستونی یا جدا، تاریخ شمسی/میلادی، ثانیه، مبلغ دارای جداکننده، ستون نوع تراکنش، مانده، شرح و شناسه مرجع پشتیبانی شود.
- `BankImportBatch`، row number، raw payload، hash فایل/ردیف، حساب بانکی، کاربر، زمان، نتیجه و error report ذخیره شوند.
- پروفایل بانک قابل تنظیم باشد؛ هیچ قالب بانک خاص، محدوده ثابت ردیف سربرگ یا نام ستون تنها فرض ثابت موتور نباشد.
- ردیف اصلی و کارمزد مستقل نگه داشته شوند؛ زمان/مبلغ/شماره مرجع مشابه دلیل کافی برای merge نیست.
- تشخیص تکراری از شناسه مرجع، حساب، جهت، تاریخ/زمان، مبلغ، مانده و شرح بهره بگیرد و نتیجه مشکوک را برای بررسی بدهد.

### تطبیق و مغایرت‌گیری
- تراکنش بانکی imported با voucher/receipt/payment/transfer احتمالی link شود؛ تطبیق پیشنهادی به‌معنی ثبت دریافت/پرداخت جدید نیست.
- تطبیق exact، مبلغ مشابه با تاریخ نزدیک، partial payment، کارمزد جدا، تراکنش بی‌سند، reversal و اختلاف مانده را جدا کنید.
- کاربر می‌تواند match، unmatch با مجوز و دلیل، یا mark as reviewed انجام دهد. Audit log لازم است.
- مانده فایل بانک و مانده دفتر بانکی داخلی را با opening/closing balance و بازه تاریخ reconcile کن؛ فرمول دقیق و علامت جهت ثابت باشد.

### چک و اسناد پرداخت
- Cheque/PaymentInstrument شامل صادرکننده، دریافت‌کننده، بانک/شعبه، شماره/شناسه، مبلغ، سررسید، تاریخ صدور، وضعیت، مرتبط به حساب/سند و تاریخچه وضعیت باشد.
- وضعیت‌های پیشنهادی مثل draft, issued, delivered, deposited, cleared, bounced, cancelled را فقط پس از بررسی گردش واقعی تصویب کن.
- تغییر وضعیت، برگشت چک، کارمزد و اثر حسابداری با سند مرجع و جلوگیری از ثبت دوباره انجام شود.

### معیار پذیرش
فایل‌های نمونه موجود و فایل متفاوت، تاریخ یک‌ستونی/جدا، ثانیه، کارمزد مجزا، ردیف تکراری، تکرار batch، تراکنش مشابه، partial match، unmatch و چک برگشتی آزموده شوند.


## قرارداد مشترک اجرا (الزامی)

این پرامپت را در مخزن واقعی اجرا کن، نه بر اساس حدس. قبل از تغییر، دستور مادر و اسناد مربوط را بخوان؛ `git status`، branch و commit را ثبت کن؛ تغییرات کاربر را دست‌نخورده نگه دار. محدوده این پرامپت تنها محدوده مجاز همین نوبت است. قبل از پیاده‌سازی، فایل‌های محتمل، وابستگی‌ها، خطر داده، اثر UI/مجوز/گزارش، migration و تست را مشخص کن. اگر یکی از قواعد تجاری لازم نامشخص است، به‌جای حدس‌زدن تصمیم باز ثبت کن و بخش وابسته را اجرا نکن. پس از تغییر، build و تست واقعی اجرا کن، diff را مرور کن، اسناد را به‌روز کن و گزارش انتهایی قالب دستور مادر را بده. موفقیت build یا تست، سازگاری Windows 7 یا آفلاین‌بودن را بدون شواهد ادعا نکن. در این نوبت به پرامپت بعدی نرو.
