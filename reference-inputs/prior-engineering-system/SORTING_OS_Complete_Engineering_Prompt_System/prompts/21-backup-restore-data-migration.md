# فاز 21 — پشتیبان‌گیری، بازیابی و انتقال داده تاریخی

**شناسه:** SORTING-OS-P21  
**محدوده:** پشتیبان فقط وقتی معتبر است که بازیابی آن آزموده شده باشد.

## دستور قابل کپی برای عامل برنامه‌نویس

تو در حال کار روی مخزن واقعی SORTING OS هستی. دستور مادر `MASTER_PROMPT.md` و فایل‌های مرجع `PROJECT_SPEC.md` و مستندات مرتبط را رعایت کن. **فقط همین مرحله را اجرا کن؛ فازهای بعد را آغاز نکن.**

### هدف
پشتیبان‌گیری و بازیابی محلی قابل اعتماد و مسیر انتقال داده تاریخی ایجاد کن.

### پشتیبان/بازیابی
- backup شامل تمام اطلاعات لازم برای اجرای مجدد باشد: DB سازگار، schema/version metadata، فایل‌های ضمیمه محلی و تنظیمات مجاز؛ credential یا داده محرمانه اضافی وارد bundle نشود.
- پشتیبان‌گیری هنگام عملیات فعال با قفل/transaction مناسب انجام شود؛ فایل ابتدا در مسیر موقت نوشته، صحت‌سنجی و سپس به مقصد نهایی rename شود.
- نام‌گذاری تاریخ‌دار، retention قابل تنظیم، مقصد محلی/رسانه جداگانه و نمایش تاریخ آخرین backup ارائه کن؛ صرفاً کپی DB در حال نوشتن را امن فرض نکن.
- بازیابی با تأیید مجوز و هشدار واضح انجام شود؛ قبل از overwrite خودکار از دیتابیس فعلی پشتیبان بگیر؛ checksum، نسخه schema و سازگاری نسخه برنامه را بررسی کن.
- بعد از restore، integrity check، شمارش رکوردهای کلیدی، آخرین سندها و audit marker اجرا شود.
- بازیابی خراب/ناتمام نباید دیتابیس فعال را نیمه‌جایگزین کند؛ rollback واضح داشته باشد.

### انتقال داده تاریخی
- ابزار import بر پایه pipeline عمومی؛ ابتدا preview/mapping/dedupe/owner matching/reconciliation.
- داده قدیمی بدون سند مرجع به‌عنوان opening balance کنترل‌شده ثبت شود، نه مقدار مستقیم مانده.
- dry-run، گزارش اختلاف قبل/بعد، mapping شناسه‌های قدیمی و فایل خطا الزامی است.
- برای مالکیت نامعلوم، سند تکراری، شماره ملی متعارض یا مانده ناسازگار، صف بررسی ایجاد کن؛ به‌جای auto-merge، داده را حفظ کن.

### معیار پذیرش
backup در مسیر بد، دیسک پر، فایل ناقص، database locked، نسخه ناسازگار، restore در محیط تمیز و نمونه migration واقعی تست شود؛ بازیابی باید یکبار عملی نشان داده شود.


## قرارداد مشترک اجرا (الزامی)

این پرامپت را در مخزن واقعی اجرا کن، نه بر اساس حدس. قبل از تغییر، دستور مادر و اسناد مربوط را بخوان؛ `git status`، branch و commit را ثبت کن؛ تغییرات کاربر را دست‌نخورده نگه دار. محدوده این پرامپت تنها محدوده مجاز همین نوبت است. قبل از پیاده‌سازی، فایل‌های محتمل، وابستگی‌ها، خطر داده، اثر UI/مجوز/گزارش، migration و تست را مشخص کن. اگر یکی از قواعد تجاری لازم نامشخص است، به‌جای حدس‌زدن تصمیم باز ثبت کن و بخش وابسته را اجرا نکن. پس از تغییر، build و تست واقعی اجرا کن، diff را مرور کن، اسناد را به‌روز کن و گزارش انتهایی قالب دستور مادر را بده. موفقیت build یا تست، سازگاری Windows 7 یا آفلاین‌بودن را بدون شواهد ادعا نکن. در این نوبت به پرامپت بعدی نرو.
