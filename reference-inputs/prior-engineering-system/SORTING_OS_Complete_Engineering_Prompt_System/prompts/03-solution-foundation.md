# فاز 03 — پوسته برنامه و زیرساخت پایه

**شناسه:** SORTING-OS-P03  
**محدوده:** زیرساخت پایدار پیش از قابلیت تجاری.

## دستور قابل کپی برای عامل برنامه‌نویس

تو در حال کار روی مخزن واقعی SORTING OS هستی. دستور مادر `MASTER_PROMPT.md` و فایل‌های مرجع `PROJECT_SPEC.md` و مستندات مرتبط را رعایت کن. **فقط همین مرحله را اجرا کن؛ فازهای بعد را آغاز نکن.**

### هدف
پایه مشترکی بساز که همه ماژول‌ها بعداً بدون کپی‌کاری به آن وصل شوند.

### کارهای دقیق
- ساختار solution/project موجود را بازاستفاده کن؛ لایه‌ها را متناسب با پیچیدگی واقعی جدا کن، نه با تعداد زیاد پروژه‌های بی‌دلیل.
- تنظیمات محلی نسخه‌دار و اعتبارسنجی‌شده بساز؛ secretهای ثابت داخل سورس یا فایل نمونه عملیاتی قرار نده.
- logging ساختاریافته با شناسه عملیات، شناسه سند، سطح خطا و همبستگی ایجاد کن؛ داده ملی/حساب بانکی/اطلاعات حساس در log ظاهر نشوند.
- مدیریت خطای متمرکز، پیام خطای قابل‌فهم فارسی و مسیر جزئیات فنی امن پیاده کن.
- لایه persistence، تراکنش، timeout، قفل‌گذاری مناسب، مدیریت قطع/خرابی دیتابیس و migration runner را تکمیل کن.
- schema version، database initialization و upgrade از نسخه قبلی را جدا طراحی کن. migration شکست‌خورده نباید دیتابیس نیمه‌تغییر‌یافته باقی بگذارد.
- راهکارهای restart persistence، crash recovery، file locking و بستن امن را آزمون کن.
- health diagnostics محلی بساز: محل دیتابیس، فضای آزاد تقریبی، آخرین backup، نسخه برنامه/schema و خطاهای قابل اقدام.
- هیچ لاگ یا diagnostic را بی‌اجازه به شبکه ارسال نکن.

### آزمون‌های ضروری
migration از دیتابیس خالی؛ ارتقا از نسخه قبلی؛ rollback در صورت پشتیبانی؛ شکست تراکنش؛ بازگشت داده پس از restart؛ lock شدن دیتابیس؛ مسیر فاقد دسترسی؛ فایل backup ناقص؛ لاگ بدون افشای داده حساس.

### معیار پذیرش
زیرساخت از UI قابل استفاده باشد، اما هنوز ادعای تکمیل هیچ گردش تجاری نشده باشد.


## قرارداد مشترک اجرا (الزامی)

این پرامپت را در مخزن واقعی اجرا کن، نه بر اساس حدس. قبل از تغییر، دستور مادر و اسناد مربوط را بخوان؛ `git status`، branch و commit را ثبت کن؛ تغییرات کاربر را دست‌نخورده نگه دار. محدوده این پرامپت تنها محدوده مجاز همین نوبت است. قبل از پیاده‌سازی، فایل‌های محتمل، وابستگی‌ها، خطر داده، اثر UI/مجوز/گزارش، migration و تست را مشخص کن. اگر یکی از قواعد تجاری لازم نامشخص است، به‌جای حدس‌زدن تصمیم باز ثبت کن و بخش وابسته را اجرا نکن. پس از تغییر، build و تست واقعی اجرا کن، diff را مرور کن، اسناد را به‌روز کن و گزارش انتهایی قالب دستور مادر را بده. موفقیت build یا تست، سازگاری Windows 7 یا آفلاین‌بودن را بدون شواهد ادعا نکن. در این نوبت به پرامپت بعدی نرو.
