# فاز 25 — استقرار آزمایشی، بهره‌برداری و آموزش

**شناسه:** SORTING-OS-P25  
**محدوده:** پیش از استفاده واقعی، فرایند روزانه و مسیر بازگشت آماده باشد.

## دستور قابل کپی برای عامل برنامه‌نویس

تو در حال کار روی مخزن واقعی SORTING OS هستی. دستور مادر `MASTER_PROMPT.md` و فایل‌های مرجع `PROJECT_SPEC.md` و مستندات مرتبط را رعایت کن. **فقط همین مرحله را اجرا کن؛ فازهای بعد را آغاز نکن.**

### هدف
سامانه را از حالت release candidate به بهره‌برداری کنترل‌شده منتقل کن؛ بدون اینکه داده واقعی قبل از اثبات بازیابی یا آموزش وارد شود.

### کارهای دقیق
1. runbook اپراتور و مدیر تهیه کن: شروع روز، ثبت باسکول، ایجاد محموله، سورتینگ، انبار، بارگیری، فاکتور، صافی، دریافت/پرداخت، چک، import bank، گزارش روزانه، backup پایان روز و قفل کاربر.
2. تعریف نقش/دسترسی را همراه صاحب کسب‌وکار بازبینی کن و برای هر کاربر کمترین مجوز لازم را بده.
3. مهاجرت داده با batch آزمایشی انجام بده؛ تعداد اشخاص، مانده‌ها، محموله‌ها و اسناد قبل/بعد را reconcile کن و موارد مبهم را تا زمان بررسی در صف نگه دار.
4. طرح pilot مشخص کن: دامنه محدود، زمان، مسئول، معیار stop/go، مسیر ثبت مشکلات، backup قبل/بعد و روش برگشت به روش دستی/سیستم قبلی.
5. آموزش کوتاه بر اساس وظیفه و سناریوی واقعی؛ نه صرفاً راهنمای کلی. عملیات اصلاحیه، خطای توزین، duplicate import، پرینتر قطع و restore را تمرین کن.
6. مانیتورینگ محلی و error log با حداقل اطلاعات حساس را مستقر کن؛ فرستادن گزارش به اینترنت ممنوع مگر توافق جداگانه صریح.
7. checklist پایان روز: کارهای معلق، مغایرت موجودی، اسناد بدون سند منبع، صافی‌های باز، بانک تطبیق‌نشده، آخرین backup و فضای آزاد.
8. ورود به بهره‌برداری کامل فقط پس از امضای گیت‌های داده، پایداری، امنیت و Windows 7/آفلاین بر مبنای محیط واقعی.

### معیار پذیرش
pilot با داده کنترل‌شده پایان‌یافته باشد؛ مشکلات بحرانی بسته یا دارای برنامه توقف باشند؛ مسئول و روش بازیابی معلوم؛ آموزش و runbook تحویل شده باشد.


## قرارداد مشترک اجرا (الزامی)

این پرامپت را در مخزن واقعی اجرا کن، نه بر اساس حدس. قبل از تغییر، دستور مادر و اسناد مربوط را بخوان؛ `git status`، branch و commit را ثبت کن؛ تغییرات کاربر را دست‌نخورده نگه دار. محدوده این پرامپت تنها محدوده مجاز همین نوبت است. قبل از پیاده‌سازی، فایل‌های محتمل، وابستگی‌ها، خطر داده، اثر UI/مجوز/گزارش، migration و تست را مشخص کن. اگر یکی از قواعد تجاری لازم نامشخص است، به‌جای حدس‌زدن تصمیم باز ثبت کن و بخش وابسته را اجرا نکن. پس از تغییر، build و تست واقعی اجرا کن، diff را مرور کن، اسناد را به‌روز کن و گزارش انتهایی قالب دستور مادر را بده. موفقیت build یا تست، سازگاری Windows 7 یا آفلاین‌بودن را بدون شواهد ادعا نکن. در این نوبت به پرامپت بعدی نرو.
