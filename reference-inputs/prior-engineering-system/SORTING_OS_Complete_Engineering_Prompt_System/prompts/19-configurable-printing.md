# فاز 19 — طراح قالب چاپ و پیش‌نمایش

**شناسه:** SORTING-OS-P19  
**محدوده:** چاپ باید کنترل‌شده، محلی و مبتنی بر سند واقعی باشد.

## دستور قابل کپی برای عامل برنامه‌نویس

تو در حال کار روی مخزن واقعی SORTING OS هستی. دستور مادر `MASTER_PROMPT.md` و فایل‌های مرجع `PROJECT_SPEC.md` و مستندات مرتبط را رعایت کن. **فقط همین مرحله را اجرا کن؛ فازهای بعد را آغاز نکن.**

### هدف
یک زیرسامانه عمومی برای قالب چاپ بساز تا کاربر بتواند پس از فشردن چاپ، قالب معتبر را انتخاب/تنظیم و پیش‌نمایش کند؛ بدون اینکه هر سند طراح جداگانه و ناسازگار داشته باشد.

### امکانات
- قالب برای انواع سند: رسید باسکول، بارنامه/حواله، فاکتور خرید/فروش، لیست محموله، گزارش صافی، گردش حساب، تسویه و گزارش انبار.
- تنظیم کاغذ A4/A5 و اندازه سفارشی در صورت حمایت چاپگر، عمودی/افقی، حاشیه، فاصله، فونت محلی، اندازه/وزن متن، ستون‌ها، ترتیب ستون، عرض، تراز RTL/LTR، نمایش/مخفی‌کردن فیلد، تیتر، زیرتیتر، متن ثابت، امضا/مهر جای‌نگهدار و footer/page number.
- متن ثابت و نام قالب توسط کاربر تنظیم شود، با پیش‌نمایش و اعتبارسنجی placeholder؛ placeholder ناشناخته خروجی خام یا خطای پنهان ندهد.
- اطلاعات پویا فقط از سند و روابط مجاز خوانده شود. فیلد محاسباتی را در template تکراراً بازحساب نکن؛ از view model معتبر استفاده کن.
- برگه‌ها و ردیف‌های چندصفحه‌ای، تکرار header جدول، ردیف جمع، جلوگیری از شکستن نامناسب، سطر طولانی و فارسی/عدد/کد mixed-direction بررسی شوند.
- انتخاب ردیف‌های مرتبط مثل محموله‌ها یا معاملات یک شخص باید قبل از چاپ قابل انتخاب باشد و بر چاپ snapshot قابل ردیابی اثر بگذارد.
- قالب پیش‌فرض قابل بازگردانی و نسخه‌های قبلی قابل انتخاب باشند. تغییر قالب نباید سند اصلی یا محاسبات آن را تغییر دهد.
- پرینت preview قبل از پرینت واقعی، انتخاب چاپگر، ذخیره PDF فقط اگر runtime و سیاست مجوز آن را پشتیبانی می‌کند؛ هیچ چاپ/PDF آنلاین.

### معیار پذیرش
A4/A5، RTL، اعداد، چند صفحه، دیتای خالی، field permission, placeholder غلط، ستون انتخابی، متن ثابت، پرینتر واقعی/VM و template restore آزموده شوند.


## قرارداد مشترک اجرا (الزامی)

این پرامپت را در مخزن واقعی اجرا کن، نه بر اساس حدس. قبل از تغییر، دستور مادر و اسناد مربوط را بخوان؛ `git status`، branch و commit را ثبت کن؛ تغییرات کاربر را دست‌نخورده نگه دار. محدوده این پرامپت تنها محدوده مجاز همین نوبت است. قبل از پیاده‌سازی، فایل‌های محتمل، وابستگی‌ها، خطر داده، اثر UI/مجوز/گزارش، migration و تست را مشخص کن. اگر یکی از قواعد تجاری لازم نامشخص است، به‌جای حدس‌زدن تصمیم باز ثبت کن و بخش وابسته را اجرا نکن. پس از تغییر، build و تست واقعی اجرا کن، diff را مرور کن، اسناد را به‌روز کن و گزارش انتهایی قالب دستور مادر را بده. موفقیت build یا تست، سازگاری Windows 7 یا آفلاین‌بودن را بدون شواهد ادعا نکن. در این نوبت به پرامپت بعدی نرو.
